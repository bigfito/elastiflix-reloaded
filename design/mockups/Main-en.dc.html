Operator

multi-match searches both fields, title and original_title, with the best_fields type: each field is scored separately and the best match counts. With AND, all the words must appear in the same field.

Retrieval with BM25: each movie’s relevance is computed with BM25, the default scoring algorithm Elasticsearch uses for text fields. It favors query terms that appear in the field and are rare in the catalog, and adjusts the score for field length.

Vector component · k-NN
Vector k-NN

{{vectorDims}} dimensions. It’s one of the three vector representations of the plot (plot). More dimensions usually capture more nuances of meaning, at the cost of more memory and more expensive comparisons.

Maximum number of results the vector search returns, after merging the candidates from all shards; they’re split into pages of 25, 50 or 100. It must be less than or equal to num_candidates. In hybrid mode it also sets how many results from each list go into the fusion and how many combined results you can page through.

Candidates evaluated on each shard before keeping the best k. Raising it tends to improve accuracy, at the cost of longer response times. Maximum 10,000.

{{knnErrorText}}

k-NN (k nearest neighbors): your query is turned into a vector, and the search looks for the movies whose plot has the closest vector. Elasticsearch does this approximately over an HNSW graph, without comparing against the whole catalog, which makes it fast but not always exact.

Fusion · RRF

Reciprocal Rank Fusion: Elasticsearch runs the BM25 search and the k-NN search separately and combines the two lists by each movie’s position in them, not by its score, because BM25 scores and vector similarity are on different scales. A movie that ranks high in both lists rises in the final result.
