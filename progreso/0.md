- 0.2: el plugin generó la distribución `only-script` (sin `maven-wrapper.jar` en el repo). Se versionan solo `mvnw`, `mvnw.cmd` y `.mvn/wrapper/maven-wrapper.properties`, como pide el plan.
- 0.3: el POM padre declara los cuatro módulos. Maven rechaza un padre cuyos módulos no tienen `pom.xml`, así que esta tarea deja un POM mínimo (padre, `artifactId`, nombre) en cada módulo. La tarea 0.4 les agrega dependencias, código y configuración. El plan no fija la versión de `maven-enforcer-plugin`; se usa 3.6.3.
- 0.4: las versiones de los módulos hermanos y de `archunit-junit6` viven en `<dependencyManagement>` del padre. Los POM hijos no declaran versión. `ElastiflixApplication` es el ejemplo de `docs/convenciones-java.md` §6, sin cambios.
- 0.5: `includeTestSourceDirectory` y `includeTests` quedan en false para que Checkstyle y PMD solo miren `src/main/java`, como pide el plan. `linkXRef` de PMD está en false para no generar el sitio de referencias cruzadas. No se tocó `config/`.
- 0.6: el padre de Spring Boot ya declara la ejecución de Failsafe en `pluginManagement`. El perfil `it` solo activa el plugin y limita las clases a `**/*IT.java`; una segunda ejecución las corría dos veces. Surefire excluye `**/*IT.java` para que `./mvnw verify` no las lance. `EnvironmentIT` usa `@Autowired` en el constructor: Spring no inyecta el constructor de una prueba sin esa anotación (no es inyección por campo). La prueba no imprime la URL ni la API key.
